# Q-0014. Безопасное изменение, зависимости и каскадные операции

**Status:** OPEN  
**Area:** Editing / Safety  
**Source:** USE-0002  
**Created:** 2026-10-01

## Вопрос

Как IMXO должен определять семантику безопасных операций изменения и удаления над связанным структурированным содержимым, чтобы корректная реализация могла обработать всю достоверно известную цепочку зависимостей и определить, завершена ли операция успешно?

## Контекст

`USE-0002` установил ожидаемое поведение сценария: удалённое содержание не должно сохраняться внутри данного конечного файла в связанных или производных представлениях только потому, что они находятся в другой части структуры.

При этом конкретный механизм не должен приниматься внутри информативного `USE`. Вопрос связывает семантику операции с логической моделью `Q-0003`, физической моделью `Q-0002`, SDK `Q-0011` и моделью соответствия `Q-0012`.

## Область вопроса

- различие между скрытием (`hide`), заменой (`replace`), удалением (`delete`), санитизацией (`sanitize`) и обрезкой (`crop`);
- граница одной логической операции;
- обход известных зависимостей и каскадное удаление;
- частично затронутые и полностью вложенные зависимые объекты;
- отличие зависимости от простого геометрического пересечения;
- производные представления, хэши и другие производные значения;
- несколько альтернативных разметок и признание разметки устаревшей;
- предыдущие состояния внутри того же файла;
- непрозрачные вложенные данные и расширения;
- поведение при невозможности безопасно обработать зависимость;
- целостность операции при сбое и проверка результата после изменения;
- граница между обязанностями формата, библиотеки и приложения.

Q-0014 не определяет конкретный формат ссылок, структуру графа зависимостей, обязательную полную пересборку файла, конкретный API библиотеки, обязательное применение искусственного интеллекта, конкретную модель транзакционной записи или встроенную криптографию.
