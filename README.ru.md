<p align="center"><strong>IMXO — Image Model eXchange Object</strong></p>

IMXO — открытый формат и стандарт структурированного изображения, предназначенный для объединения визуального содержимого и структурированных машиночитаемых данных в одном расширяемом объекте.

Проект исследует модель, в которой изображение не ограничивается плоским растром. Файл IMXO потенциально может содержать растровые и векторные представления, текст, семантические области, аннотации, сведения о происхождении данных, механизмы целостности, данные доступности и несколько связанных представлений одного визуального объекта.

> IMXO находится на стадии исследования и раннего проектирования. Формат файла, структура контейнера, логическая объектная модель и правила соответствия стандарту пока не зафиксированы окончательно.

## Цели

IMXO проектируется как общее открытое представление изображений, пригодное для людей, приложений, ИИ-систем, средств компьютерного зрения, редакторов, просмотрщиков, средств захвата экрана и архивных сценариев.

Проект должен, среди прочего, позволять представлять:

- растровые изображения;
- векторные представления и оверлеи;
- текст, связанный с областями изображения;
- семантические области и связи;
- несколько наборов аннотаций;
- аннотации компьютерного зрения;
- происхождение и источник данных;
- сведения для проверки целостности и доверия;
- описания для доступности;
- несколько представлений одного изображения или объекта;
- безопасные расширения с сохранением неизвестных расширений.

IMXO не ставит целью заменить все существующие растровые и векторные кодеки. Существующие кодеки могут использоваться как отдельные представления внутри более общей модели IMXO.

## Статический и пассивный формат

Для первой версии стандарта принят жёсткий принцип:

**IMXO v0.1 не должен содержать исполняемого или динамического поведения.**

Формат должен оставаться статическим и пассивным. В него не должны встраиваться JavaScript, макросы, обработчики событий, автоматические сетевые запросы, исполняемые сценарии, внешне обновляемые динамические поля и аналогичное активное поведение.

## Сначала исследование

Проект не исходит из предположения, что обязательно потребуется полностью новый контейнер.

До окончательного проектирования физической и детальной логической модели должны быть исследованы существующие контейнерные и графические архитектуры, в том числе:

- JUMBF / JLINK;
- ISO BMFF / HEIF;
- RIFF;
- архитектура PNG chunks;
- TIFF / BigTIFF;
- ZIP-подобные контейнерные модели;
- другие релевантные стандарты и контейнерные решения, обнаруженные в ходе исследования.

Решение между собственным контейнером IMXO, профилем на основе существующего контейнера или гибридным подходом должно приниматься только после этого исследования.
