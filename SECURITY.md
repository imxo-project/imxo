# Security policy

IMXO is currently in the research and early design stage. There is no released parser, encoder, decoder, SDK, or reference implementation yet.

## Reporting a potentially sensitive vulnerability

Do not report an unpatched vulnerability or other potentially sensitive security issue through a public GitHub Issue.

Contact the project maintainer privately:

- Email: [fmalkov91@gmail.com](mailto:fmalkov91@gmail.com)
- Telegram: [@FyodorMalkov](https://t.me/FyodorMalkov)

Include enough information to understand and reproduce the issue, but do not send secrets, personal data, or unrelated confidential material.

The project does not currently promise a response time, remediation SLA, or bug bounty.

## Public security research

Public research and discussion about the IMXO threat model are welcome. Appropriate public topics include parser robustness, discrepancies between visual and structured layers, misleading metadata, prompt-injection-like content, provenance forgery, annotation substitution, secret leakage, integrity verification, and trust-state presentation.

Keep a concrete unpatched vulnerability private until it can be assessed. General architectural analysis and threat-model proposals may be submitted through the normal contribution process.
